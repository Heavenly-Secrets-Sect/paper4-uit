# Per-cell provenance, tier1_core14

Generated by `build_core14_provenance.py`. No wall-clock time recorded.

Labels every one of the **308** cells in the 14-node core grid (14 nodes x 22 quarters), so a reader can tell an audited number from a simulated one without leaving the page.

## The window, derived rather than asserted

| Window | n | Rule |
|---|---:|---|
| `complete` | **21** | every one of the 14 nodes has a value |
| `macro_observed` | **20** | loai_du_lieu == 'real' in 4.ViMo_TheoQuy |
| `defensible` | **19** | complete AND macro_observed |

`defensible` is **19 quarters**, 2020Q2 to 2024Q4. That is where the repository's figure comes from, and it now follows from the source flags instead of from convention.

> **NOT a window in which every cell is real. The seven banking nodes are simulated_calibrated in all of them, and no window of this grid is fully observed.**

Two boundaries set it, and they are different boundaries:

- 2020Q1 drops out of `complete` because `stock_return_qoq_pct` has no prior quarter
  to difference against. That is arithmetic, not a data gap.
- 2025Q1 and 2025Q2 drop out of `macro_observed` because `4.ViMo_TheoQuy` flags those
  rows `simulated_calibrated`. The macro block is not uniformly real, and the boundary
  sits inside the matrix rather than at its edge.

compare against. It is counted here and nowhere else.

## What this does not do

It describes the matrix. It writes nothing into `node_sets.yaml`, the prior graph, the
canonical node set or any discovery input, and it changes no value in
`candidate_quarterly_matrix_raw.csv`. Correcting a label that lives in the discovery config is
a separate change with its own review.
